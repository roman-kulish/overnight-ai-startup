# Meditate to Your Shares

## Concept

A user enters a stock or crypto ticker. The app fetches live price data from Yahoo Finance, picks a **Bhāva** (a Buddhist-flavored "state of being") based on the ticker's recent direction and volatility, and assembles a pool of **18-24 meditation phrases** — 6 freshly generated by Workers AI plus 12-18 hand-crafted static phrases from a per-bhāva library in the Worker. A breathing orb at center stage displays the ticker, price, and a 30-day sparkline. Around the orb, six slots cycle 12 of those phrases in and out — each one fades in, holds for a breath, and fades out. The breath cycle itself responds to the market: faster and shallower when volatility is high, deeper and slower when it's calm. Ambient music from Uppbeat plays on loop; subtle SFX are synthesised via the Web Audio API on phase changes, price events, and bhāva transitions.

The parody is in the friction between **Buddhist mindfulness vocabulary** and **finance-bro delusion** — your portfolio is a sutra, your cost basis is a koan, your ticker is a prayer wheel.

**No avatar.** This is a meditation app, not a roast. The orb is the only character.

**No session cap.** Once the user begins, the meditation continues until they choose to end it. The KV-cached phrase pool keeps LLM cost near zero, the seeded shuffle makes each session feel fresh, and the lack of a hard end feels appropriate for an ambient practice.

## Session lifecycle

1. **Idle** — user enters a ticker in an input card on a dark mystic background. Subtitle: *"A mindfulness practice for the financially devastated."*
2. **Loading** — 8-step sequence validates the ticker, fetches the quote, and (on first call for this ticker+bhāva combo) generates the dynamic phrase batch. Music has not yet started (autoplay requires a user gesture).
3. **Meditating** — the orb appears, music starts, breath cycle begins, phrases start cycling. Quote polling drives orb updates. Session continues indefinitely until user action.
4. **End session** — only triggered by the user clicking "End Session". Shows a final card with duration, bhāva, session sparkline, and Uppbeat attribution. Sends the user back to the input screen.

When the browser tab is hidden (`document.visibilityState === 'hidden'`), quote polling pauses. On focus, the next quote fetch fires immediately. This keeps idle tabs from spending AI Gateway budget.

## Data source

**Yahoo Finance v8 Chart API** (no API key, no CORS issue from a Worker):

```
GET https://query1.finance.yahoo.com/v8/finance/chart/{TICKER}?interval=1d&range=1mo
User-Agent: Mozilla/5.0 (compatible; OvernightAI/1.0)
```

Returns a JSON envelope. We read:

- `chart.result[0].meta.regularMarketPrice` — current price
- `chart.result[0].meta.chartPreviousClose` — prior close (for change %)
- `chart.result[0].meta.regularMarketDayHigh` / `regularMarketDayLow` — day range
- `chart.result[0].meta.currency` — display currency
- `chart.result[0].meta.fullExchangeName` — exchange label
- `chart.result[0].meta.longName` — full company/fund name
- `chart.result[0].indicators.quote[0].close` — last 21 closes for sparkline and volatility

If `chart.error` is present (e.g. `Not Found`), return `400 { ok: false, error: "Ticker not found" }`. The `User-Agent` header is required — Yahoo 403s without it.

Supports stocks (AAPL, TSLA, GME), crypto (BTC-USD, ETH-USD, DOGE-USD), ETFs (SPY, QQQ), and class shares (BRK-B). Ticker validator regex: `^[A-Z0-9\-]{1,10}$` (uppercased, allow `-` for crypto/BRK.B-style tickers, mapped to `-` for Yahoo).

## KV caching (the cost-safety net)

Two Cloudflare KV namespaces eliminate the "always call Yahoo / always call the LLM" problem:

### Quote cache (`meditate_quotes` namespace)
- **Key**: `quote:{TICKER}` (uppercased)
- **Value**: the full parsed quote envelope (price, change, changePct, dayHigh, dayLow, sparkline, bhava, mood, breathCycle, volatility, longName, currency)
- **TTL**: 30 seconds
- **Behaviour**: every `/api/meditate/quote` request first reads the cache. On hit, returns the cached value with `stale: true` (so the UI can show a small "stale" indicator). On miss, fetches from Yahoo, parses, computes deterministic fields, writes the cache, returns `stale: false`.
- **Why 30s**: matches the client polling cadence. A typical session makes ~4 quote requests per minute; the KV cache means only 1 of every 2 actually hits Yahoo.
- **Yahoo rate-limiting**: this 50%+ reduction in Yahoo call rate is the primary defence against the 403/429 problem. If Yahoo does 403/429, the Worker surfaces `502 { ok: false, error: "Quote feed unavailable, try again" }` — no fallback to a second vendor (extra dependencies are not worth the marginal benefit). If sustained 403/429 becomes a real problem, a second source can be added later.

### Phrase cache (`meditate_phrases` namespace)
- **Key**: `phrases:{TICKER}:{BHAVA_KEY}` where `BHAVA_KEY` is the ASCII-safe bhāva name (`Sunyata`, `Dukkha`, `Upekha`, `Sankhara`, `Piti`, `Moha`)
- **Value**: a JSON envelope `{ dynamic: string[6], generatedAt: <unix> }` — the 6 LLM-generated phrases only (the static phrases are always pulled fresh from code, not cached)
- **TTL**: 2 hours
- **Behaviour**: `/api/meditate` first reads the phrase cache. On hit, returns `{ dynamic: cached, static: <from code> }` — no LLM call. On miss (or expired), calls the LLM, writes the cache, returns the same shape.
- **Why 2h**: market sentiment for the same ticker + bhāva is effectively the same for 2 hours. The TTL is long enough that most users hit cache, short enough that bhāva transitions pick up new phrasing within a session.
- **Bhāva transitions**: when the user crosses a bhāva threshold mid-session (e.g. Dukkha → Śūnyatā), the new bhāva's cache key is a miss, so a fresh LLM call fires. This is correct — the meditation should respond to a meaningful shift in market state.

### wrangler.jsonc additions

```jsonc
"kv_namespaces": [
  { "binding": "QUOTE_CACHE",   "id": "<meditate_quotes_id>" },
  { "binding": "PHRASE_CACHE",  "id": "<meditate_phrases_id>" }
]
```

## Two-endpoint architecture

Clean separation between **fast quote polling** (no LLM, KV-cached) and **slow phrase generation** (LLM, KV-cached).

### `POST /api/meditate/quote`
- No LLM. KV-cached. ~50ms round trip on cache hit, ~150ms on miss.
- Request: `{ ticker }`
- Response: `{ ok: true, quote: { ticker, longName, currency, price, change, changePct, dayHigh, dayLow, sparkline, bhava, bhavaTranslation, mood, breathCycle, volatility }, stale: <bool> }`
- Polled every **15 seconds** by the client. Paused when the tab is hidden.
- Drives the orb display (price, change %, sparkline) and the bhāva-change detection (which decides whether to trigger a phrase refresh).

### `POST /api/meditate`
- LLM call, but only on KV cache miss. ~50ms on hit, ~3-5s on miss (plus the 2h amortised cost across users).
- Request: `{ ticker, lastBhava? }`
- Response: `{ ok: true, meditation: { ticker, longName, currency, price, change, changePct, dayHigh, dayLow, sparkline, bhava, bhavaTranslation, mood, breathCycle, phrases: string[], poolSize: number, generatedAt: <unix>, cached: <bool> } }`
- Called once at session start, then **only when** the quote endpoint shows a bhāva change. If the bhāva is unchanged, the client does not re-call this endpoint; it just shuffles the cached pool locally.
- Streamable but not currently streamed — the LLM only outputs 6 short phrases, response fits in one round trip. If we add more dynamic phrases later, switch to SSE per the Roast pattern.

### Pipeline

Both routes use the shared `createAIPipelineHandler` factory from `worker/routes/shared.ts`:

1. Validate ticker (format + length).
2. Run prompt-injection detection.
3. Read from KV cache. If hit, branch to fast path.
4. On miss, fetch live quote from Yahoo Finance.
5. Compute `bhava`, `mood`, `breathCycle`, `volatility` deterministically in the Worker.
6. For `/api/meditate` only: if `dynamic` phrases are not in cache, call the LLM through the AI Gateway, write the cache, return.
7. For both: assemble the final envelope (static phrases always come from code, dynamic phrases come from cache or LLM).
8. Return the response envelope.

### When the LLM is and isn't called

| Trigger | LLM called? |
|---|---|
| First request for `(ticker, bhāva)` | **Yes** (KV miss) |
| Re-request for `(ticker, bhāva)` within 2h | **No** (KV hit) |
| Re-request after 2h TTL | **Yes** (KV miss) |
| Bhāva changes during a session (e.g. Dukkha → Śūnyatā) | **Yes** (new bhāva, new key) |
| Same bhāva, price moved | **No** (client just shuffles cached pool) |
| Tab hidden then visible | **No** (polling resumes, no LLM call) |
| User stays in session for hours | **No** (one LLM call per bhāva per 2h, max) |

In practice, a typical 30-min session with one bhāva transition produces **2 LLM calls**. Without KV cache, the same session could produce 60+ LLM calls (one per refresh tick).

## Bhāva — the mock mood

A Buddhist-flavored "state of being" picked deterministically from the ticker's recent change and volatility. Picked in the Worker, not by the LLM, so it's testable and instant.

| Change % (1d) | Volatility | Bhāva | Translation | Orb color | ASCII key (for KV) |
|---|---|---|---|---|---|
| `< −3%` | any | **Śūnyatā** | Emptiness | deep crimson `#7f1d1d` | `Sunyata` |
| `−3% to −1%` | any | **Dukkha** | Suffering | muted red `#991b1b` | `Dukkha` |
| `−1% to +1%` | low | **Upekkhā** | Equanimity | burnished gold `#ca8a04` | `Upekkha` |
| `−1% to +1%` | high | **Saṅkhāra** | Formation | amber `#d97706` | `Sankhara` |
| `+1% to +3%` | any | **Pīti** | Rapture | jade `#15803d` | `Piti` |
| `> +3%` | any | **Moha** | Delusion | bright emerald `#22c55e` | `Moha` |

Volatility is the standard deviation of the last 21 daily closes, normalised by the mean (coefficient of variation). `low < 0.015`, `high ≥ 0.015` — tuned for the threshold to feel right on the 1-month range. Unit-testable with `toBeGreaterThanOrEqual` / `toBeLessThanOrEqual`.

## Breath cycle — driven by volatility and direction

The orb **scales with the breath**. The breath cadence is computed in the Worker and passed to the client as a `breathCycle` object:

| Market state | Breath cycle (in / hold-in / out / hold-out, seconds) | LLM emphasis |
|---|---|---|
| High volatility (σ > 3%) | 3 / 4 / 5 / 4 — *faster, shallower* | "the asset trembles" |
| Low volatility (σ < 1%) | 5 / 7 / 8 / 7 — *deeper, slower* | "the asset is still" |
| Direction up | normal cycle | "rising" / "ascent" / "gains" |
| Direction down | normal cycle, slightly longer hold | "descending" / "the fall" / "release" |
| Direction flat | deep cycle | "drifting" / "equanimity" |

The orb's scale is driven by a single `requestAnimationFrame` loop in the `useBreathCycle` hook. The loop writes `transform: scale(var(--orb-scale))` directly to the orb DOM element via `style.setProperty`, with no React re-render. The CSS uses `transform: scale(var(--orb-scale, 1.0))` with no transition. 60fps guaranteed, even on mobile.

The whole screen feels like the meditation: the orb's `--orb-glow` variable drives `box-shadow` intensity, the radial gradient background breathes with the orb, and the breath phase indicator (4 dots below the orb) advances on the same clock.

## The phrase pool (50/50 static + dynamic, shuffled per session)

### Pool composition

Each `(ticker, bhāva)` produces a pool of **24 phrases**:

- **6 dynamic** — generated by the LLM, market-aware, KV-cached for 2h
- **18 static** — hand-crafted in the Worker code, one set per bhāva, no LLM call

The static library has **108 phrases total** (18 × 6 bhāvas), stored in `worker/routes/meditate-static-phrases.ts`. Each bhāva's static array is preceded by a flavor comment in the spirit of a "liturgical text" — e.g. `// From the Book of Śūnyatā, verses 1-18`. If this overloads the UI feel, drop the comments and keep the phrases clean.

Example static phrases for **Dukkha** (suffering):

```ts
// From the Book of Dukkha, verses 1-18
const STATIC_PHRASES: Record<BhavaKey, string[]> = {
  Sunyata: [ /* 18 phrases */ ],
  Dukkha: [
    'Breathe in... and acknowledge what is here.',
    'The chart has fallen. You are still here.',
    'Breathe out... and loosen your grip on the number.',
    'Every position is impermanent.',
    // ... 14 more
  ],
  Upekkhā: [ /* 18 phrases */ ],
  // ...
};
```

### Per-session shuffle

When the user clicks "Begin Meditation":

1. Client generates `sessionId = crypto.randomUUID()`
2. Client calls `/api/meditate {ticker, lastBhava}` and receives the full pool (6 dynamic + 18 static = 24 phrases)
3. Client uses a **seeded shuffle** (deterministic PRNG seeded with `sessionId`) to pick 12 of the 24
4. The 12 chosen phrases form the session's cycle
5. As the user meditates, the 12 cycle through the 6 slots (each slot holds a phrase for ~10s, total cycle = ~60s)

Different sessions pick different 12 from the same 24-pool. The user never sees the same exact cycle twice, even with KV cache returning the same phrases.

If the user meditates for a very long time and the cycle feels stale, the client can call a "shuffle again" function (bound to a keyboard shortcut or a tiny UI affordance) to re-pick 12 from the 24 without re-fetching.

### Phrase shower layout (the headline UX)

Phrases **orbit the orb** in a 6-slot hex pattern on desktop, single column on mobile:

```
         ┌───────┐
         │ slot 1│
         │       │
┌───────┤       ├───────┐
│ slot 6│       │ slot 2│
│       │  ORB  │       │
├───────┤       ├───────┤
         │       │
         │ slot 3│
         └───────┘
   (slot 4)    (slot 5)
```

Each slot:
- **Fades in** over 1.5s (ease-out, scale 0.92 → 1.0, y +8 → 0)
- **Holds** for 7s
- **Fades out** over 1.5s (ease-in, scale 1.0 → 0.92, y 0 → -8)
- **Total life**: ~10s

Pool has 12 phrases (after shuffle), 6 slots, total cycle = ~60s. With session shuffle, the cycle is different every session.

The `clamp()` values for orb size (`clamp(180px, 22vw, 280px)`) and slot offset (`clamp(180px, 20vw, 240px)`) ensure the layout works from 375px (iPhone) to 1920px (desktop) without clipping or overlap.

## The LLM prompt (refined, terse, delimited)

The LLM is a pure phrase generator. It outputs only `PHRASE:`-prefixed lines — no JSON, no meta, no prose.

**System prompt:**

```
You are a dry, sardonic mindfulness instructor. Generate exactly 6 short
meditation phrases (6-14 words each) for someone whose stock or crypto
portfolio is fluctuating. Use the provided market context as an allegory,
not as the topic.

Format: output only the 6 phrases, each on its own line, each starting with
"PHRASE:". Do not output JSON, prose, or conversational intro.

Banned words: 'center', 'inner peace', 'present', 'wealth', 'money', 'stock',
'crypto', 'yourself'. Do not use ellipses inside a phrase — use commas
instead. The final phrase should feel like it could begin the next cycle.
```

**User prompt** (carries deterministic context, computed in the Worker):

```
Ticker: TSLA. Bhāva: Dukkha. Direction: down. Volatility: medium.
Recent change: -1.17% over 1 day. Treat the descent as a slow exhale.
Metaphor to use: weather.
```

**Output shape** (parsed in the Worker, no `JSON.parse`):

```
PHRASE: Breathe in, and accept the descent.
PHRASE: The chart has fallen. You are still here.
PHRASE: Breathe out, and loosen your grip on the number.
PHRASE: Volatility is the universe's breath.
PHRASE: Hold, and let the storm pass through you.
PHRASE: Breathe in, and begin again.
```

The Worker splits on `\nPHRASE:` and trims each line. If the LLM produces fewer than 6 lines (a known llama-3.2-3b failure mode), the Worker pads with a fallback "Breathe in, and notice you are still here." to reach 6. If the LLM produces more than 6, the Worker takes the first 6. The dynamic phrases are written to KV cache as a `string[6]` array.

This delimiter approach is **more reliable than JSON** with small instruction-tuned models, which frequently break JSON syntax when generating multi-item arrays with internal punctuation. The cost is a small number of extra output tokens (the `PHRASE:` prefix on each line), easily worth the reliability gain.

## Music

Three ambient/meditation tracks, downloaded from **Uppbeat** (free tier, cleared for self-hosted use with attribution), stored at `public/audio/ambient-01.mp3`, `ambient-02.mp3`, `ambient-03.mp3`. Played via an HTML5 `<audio>` element with `loop`, `preload="auto"`. The client picks one of the three at random per session (or cycles through them; see the Track listing section).

The audio element can `preload="auto"` without a user gesture, but **cannot** `.play()` without one. The "Begin Meditation" click handler is the synchronous chain that satisfies the autoplay policy:

```ts
async function handleBegin() {
  // 1. Resume the audio context (creates it lazily)
  await audioContextRef.current?.resume()

  // 2. Start music playback
  audioRef.current?.play().catch(() => {
    // Music failed to start (e.g. file missing) — meditation continues without it
  })

  // 3. Start the session
  startSession()
}
```

The `AudioContext` is created on first call to `useAmbientAudio()` (which only runs after the component mounts, which only happens after the user clicks "Begin Meditation"). Safari and Chrome both allow `audioContext.resume()` and `audio.play()` inside this synchronous user-gesture chain.

**Per-session track selection.** Two reasonable behaviours:

- **Seeded random per session** — `trackIndex = hash(sessionId) % 3`. Different sessions hear different tracks; a returning user gets variety without us needing to download more.
- **Sequential cycle** — start with track 1, advance to 2 on the next session, 3 on the session after, then back to 1. Most predictable; easiest to debug.

Start with **seeded random**; switch to sequential if users complain. The client picks at session start and writes the result into the `Music from #Uppbeat` attribution link, so each session links to its own track's Uppbeat page.

## SFX (procedural, no extra files)

Web Audio API `OscillatorNode` for all SFX. All events respect a master mute toggle and `prefers-reduced-motion` (which also implies reduced audio). Master gain capped at 0.15 so SFX sit **under** the music, not on top.

| Event | Sound | Synthesis |
|---|---|---|
| Phase: Inhale start | low gong | sine 110Hz, attack 0.02s, decay 2.5s, lowpass 400Hz, gain 0.12 |
| Phase: Exhale start | wind chime | triangle 880Hz + 1320Hz, attack 0.005s, decay 1.8s, gain 0.06 |
| **Bhāva changed** (orb color shift) | shimmer | 4 detuned sines at 1200/1800/2400/3000Hz, 0.4s, gain 0.05 |
| Price up > 0.5% | small bell | sine 880Hz, attack 0.005s, decay 0.6s, gain 0.10 |
| Price down > 0.5% | descending tone | sine sweep 400Hz→180Hz, 1.2s, lowpass 800Hz, gain 0.10 |
| First LLM phrase arrival (session start) | shimmer | same as bhāva changed |
| End of session | full release | sine 220Hz with reverb tail, 3s, gain 0.08 |

The **bhāva-changed** event is new — when the orb color shifts because the bhāva crossed a threshold (e.g. Dukkha → Śūnyatā), play the shimmer. This makes the meditation feel emotionally responsive to the market's shift, not just its data.

Helper module: `src/audio/sfx.ts` — exports one function per event, each one creates the `AudioContext` on first call (lazy init, no audio glitch on cold start) and a `Mute` toggle that suspends all SFX calls without re-instantiating the context.

## Refresh choreography (no cap, on-demand)

```
t=0      user clicks "Begin Meditation"
         → audio context created + resumed (user gesture)
         → music starts
         → generate sessionId = crypto.randomUUID()
         → POST /api/meditate {ticker} (no lastBhava)
         → 8-step loading sequence

t≈2s     response arrives
         → if KV cache miss: LLM call fired (one of the rare ones)
         → orb colors to bhāva, breath cycle starts, phrase cycle begins
         → client picks 12 of 24 phrases via seeded shuffle with sessionId

t=15s    POST /api/meditate/quote (KV-cached)
         → orb re-renders with new price, change %, sparkline re-draws
         → if bhāva is unchanged, no phrase refresh needed
         → if bhāva changed: POST /api/meditate {ticker, lastBhava} for new pool

t=30s    another quote tick
         → only triggers a phrase refresh if bhāva crossed a threshold

t=2m, 5m, 10m, ...  same — only quote ticks, only LLM call on bhāva change

User hits "End Session"  (no auto-end)
         → audio fades out (1s)
         → final card fades in: "You have meditated. TSLA · Dukkha · 4m 12s"
         → Uppbeat attribution shown in card (links to whichever track played this session)
         → "Begin another ticker" sends user back to the input screen
         → no further LLM or quote calls
```

If the user hits **End Session** and the audio context is still in a "suspended" state (e.g. user toggled mute early and the OS suspended the context), explicitly call `audioContext.close()` to release the resource. Otherwise let it persist — the next session reuses it.

## The loading sequence

8 steps, ~400ms each, same spinning-ring pattern as `Roast.tsx`:

```
Validating ticker...
Lighting the candles...
```

## Model

`@cf/meta/llama-3.2-3b-instruct` with fallback to `@cf/meta/llama-3.2-1b-instruct`. The output is short, structured, and constrained by the delimiter format — a small instruction-tuned model is enough. The `PHRASE:` delimiter is more reliable than JSON for this model, with a parser-side fallback that pads short outputs to 6 phrases.

## Operational notes

- **Cloudflare Workers KV** has a generous free tier: 100,000 reads/day, 1,000 writes/day. Our typical session makes ~240 quote reads + 2 phrase reads + 0-2 phrase writes. Well within budget. If we hit the limit, the AI Gateway spend caps will trigger first.
- **Yahoo Finance** is rate-limited per IP. The 30s quote cache + 15s polling cadence means we hit Yahoo ~2 times per minute per user, ~120 times per hour. If multiple users share a Cloudflare egress IP, this is fine — Yahoo's per-IP rate limit is far higher than this. If we ever see 403/429 in production logs, we can drop the polling cadence to 30s.
- **LLM cost** is bounded by the bhāva × ticker × 2h matrix. With 4,000 actively-traded tickers and 6 bhāvas, the max phrase cache size is 24,000 entries. Each entry is ~500 bytes. Total: 12 MB. Free.
- **Session length** is unbounded. The 30-min cap from the previous iteration is removed. KV cache keeps cost near zero, seeded shuffle keeps it fresh, and the meditation's natural rhythm keeps it feeling bounded.
- **Uppbeat attribution** is required for all three tracks. The credit is shown in the end-session card and the idle-view footer, linking to the specific track page on Uppbeat that was played during the session.

### Desktop findings

#### Critical

**1. Right-side phrases clipped at the screen edge.** The "Hold, and do not confuse your genius..." and "Breathe in, and let the green wash over you..." phrases in the desktop screenshots run off the right edge of the viewport. The `clamp(180px, 20vw, 240px)` slot offset is too aggressive at typical laptop widths (1366-1440px).

Alternative: collapse to a 4-slot layout (top / bottom / left / right) on screens `< 1400px`, since the diagonals clip most aggressively.

```css
.phrase-slot {
```

**3. Orb looks flat.** The current orb reads as a 2D green disc with a faint gradient. The glassmorphic CSS from the Visuals section is not being applied (or is being overridden).

The double outer glow (`60px` + `120px`) gives the orb the "lantern in fog" quality. The `35% 35%` radial center creates the off-axis highlight that sells the glass effect.
